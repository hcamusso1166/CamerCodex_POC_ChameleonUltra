# A1 · Primera lectura en el laboratorio

## Chrome en Windows

Desde la raíz de la rama `feat/poc-a1-ble-rfid`, con Node.js 22 y npm, ejecutar en PowerShell:

```powershell
npm.cmd ci --ignore-scripts
npm.cmd test
npm.cmd start
```

Abrir `http://127.0.0.1:8443` en Chrome. La dirección de loopback del propio equipo admite Web Bluetooth en contexto seguro. El servidor entrega únicamente la pantalla, sus módulos y los dos archivos del SDK desde el disco local. [Web Bluetooth en Chrome](https://developer.chrome.com/docs/capabilities/bluetooth)

## Chrome en Android con HTTPS válido por USB

Preparar un teléfono de laboratorio, un cable USB de datos, Android SDK Platform Tools y mkcert en Windows. El teléfono utiliza su propia radio BLE. El túnel USB sólo transporta la página. [Android Debug Bridge](https://developer.android.com/tools/adb) · [Certificados locales y clientes móviles](https://github.com/FiloSottile/mkcert)

1. Detener la instancia HTTP con Ctrl+C. Preparar el certificado y su clave fuera del repositorio, en una carpeta privada del usuario:

   ```powershell
   $tlsA1 = Join-Path $env:LOCALAPPDATA 'CamerA1-TLS'
   New-Item -ItemType Directory -Force -Path $tlsA1 | Out-Null
   $env:A1_CERT = Join-Path $tlsA1 'localhost.pem'
   $env:A1_KEY = Join-Path $tlsA1 'localhost-key.pem'
   mkcert -cert-file $env:A1_CERT -key-file $env:A1_KEY localhost 127.0.0.1
   npm.cmd start
   ```

2. En otra terminal, habilitar depuración USB en el teléfono y autorizar ese PC. Transferir **únicamente el certificado público de la CA** e instalarlo desde los ajustes de seguridad de Android como certificado de CA de usuario. Las políticas de un teléfono administrado pueden impedirlo.

   ```powershell
   adb devices
   $caA1 = Join-Path (mkcert -CAROOT) 'rootCA.pem'
   adb push "$caA1" /sdcard/Download/CamerA1-CA.crt
   adb reverse tcp:8443 tcp:8443
   ```

3. Abrir `https://localhost:8443` en Chrome Android y comprobar que Chrome acepta el certificado sin advertencias. El servidor sigue escuchando exclusivamente en el loopback de Windows. Mantener el teléfono en primer plano.
4. Al terminar, ejecutar `adb reverse --remove tcp:8443`, quitar la CA de laboratorio del teléfono, revocar la depuración USB y detener el servidor. Abrir una PowerShell nueva para volver al modo HTTP de Windows.

## Ensayo físico a cargo del responsable

1. Cerrar la GUI si ocupa la conexión. Con Bluetooth activo y la unidad encendida en modo de aplicación, pulsar **Conectar** y seleccionar el Compact. Anotar el nombre BLE, modelo, versión de aplicación, revisión y capacidades informadas. El estado operativo requiere confirmar el modo lector.
2. Ingresar la clave A autorizada de seis bytes en el campo local. La página la mantiene en memoria durante la sesión y limpia el campo al cerrarla. La aplicación no registra tramas ni claves. Dejar desactivadas las trazas externas del SDK durante el ensayo.
3. Presentar una sola tarjeta y mantenerla inmóvil hasta terminar. Pulsar **Leer tarjeta** una vez por presentación. El escaneo y la lectura autenticada son intercambios distintos. El criterio A1 exige una selección con SAK 08, un bloque de 16 bytes y uno de los tres identificadores autorizados. La extracción toma los primeros cuatro caracteres ASCII en los rangos 0–9 o A–Z, en orden, entre esos 16 bytes. [Fuentes y límites de la Entrega 0](auditorias/ENTREGA_0_FACTIBILIDAD.md)
4. Repetir con cada tarjeta. En el acta física separada registrar fecha, commit (`git rev-parse HEAD`), unidad, firmware informado, navegador/SO, tarjeta presentada, resultado esperado (`06NR`, `08NR`, `14RR`), resultado observado y estado/error exacto.
5. Pulsar **Desconectar**. Si se cambió desde emulación, el equipo puede quedar en modo lector. Restaurar el modo anterior mediante la GUI conocida si corresponde.

## Errores y recuperación

Un fallo de lectura borra el resultado y cierra la sesión. Para una tarjeta ausente o un rechazo de autenticación, corregir la presentación o la clave y conectar de nuevo. Ante timeout o pérdida BLE, la nueva sesión impide que una respuesta tardía se acepte como lectura posterior. Ante firmware incompatible, detener el ensayo afectado y registrar paso, modelo, firmware, comando y estado tal como aparecen en pantalla. La recuperación operativa es cerrar la POC y volver a la GUI conocida.
